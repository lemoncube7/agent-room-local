# 에이전트 실행, 실시간 끼어들기, 제어 태그

## 3.1 턴 디스패치 및 끼어들기 (`hub.cjs`)
- `dispatchQueuedTurns()`가 `deliveries.state = 'queued'`를 모아 멤버별 실행.
- **작업 중(`cliBusy.has(participant)`) 끼어들기:**
  - `isAlert`와 `isCoordinated`가 아닌 일반 `priority >= 1` 메시지는 `deliverLive(participant, item)`를 호출합니다.
  - 세션이 `.steer` 또는 `.live` 인박스를 지원하면 진행 중인 턴으로 바로 끼어들어 전달되고, 미지원이면 `queued`로 남아 현재 턴 종료 후 실행됩니다.

## 3.1b 프롬프트 구조 · 순위 판정 · 조율 흐름
- 첫 턴이나 정책이 바뀐 턴에만 전체 정책(`replyPolicy`)을 보내고, 평소에는 짧은 규칙(`coreRules`)만 보낸다. 매 턴 붙는 상태 블록에는 에이전트별 모델·노력·우선순위와 한도가 들어가고, 요청은 `Current request` 머리글로 표시된다. 에이전트가 태그에 이름을 쓰면 `normalizeTagTargets`가 id로 바꾼다.
- 순위 판정 모델은 JSON을 내고 에이전트를 이름으로 가리킨다. 한도가 0%인 에이전트와 **이름이 불리지 않은 임시 작업자(`sub_kind='task'`)**는 후보에서 빠진다. 상주 서브에이전트는 기본으로 후보에 들어간다.
- `/조율 …`·`/회의 …`로 시작하는 메시지는 판정을 건너뛰고 "각자 의견 → 조율 → 동시 작업"(`/회의`는 합의안까지만)으로 간다. 이 표시(`flowBySeq`)는 **메모리에만** 있어서 허브가 재시작되면 판정 전이던 메시지는 일반 메시지로 처리된다.
- 자동 순위 방에서 "각자 의견 내고 다 나오면 상의해" 식의 한 메시지 요청은, 의견을 낸 에이전트가 2명 이상일 때만 조율 라운드로 넘어간다.
- 병렬 답변이 여러 개면 마지막에 답한 에이전트가 정리(`maybeWrapUp`)를 맡는다.
- 임시 작업자의 답은 부모에게만 가는 개인 메시지(`recipient`)이며 방에서는 접혀 보인다. 부모가 보고를 처리한 턴이 끝나면 작업자가 정리된다. **서브에이전트(상주·임시 모두)의 답은 기본적으로 부모를 깨운다.** 깨우지 않을 답에는 `[[NOT_CALL_PARENT]]`를 그 줄에 단독으로 쓴다(3.2).

## 3.2 제어 태그 (에이전트 응답 본문에서 파싱)
- **위치 규칙:** 태그는 응답의 어느 줄에든 **그 줄에 태그만 단독으로** 있으면 인식한다(첫 줄일 필요 없음). 문장 중간에 섞인 태그, 인용문·코드 블록 속 태그는 무시한다.
- `[[WORK: 제목]]` / `[[DONE]]` / `[[CONTINUE]]` / `[[WAIT: 이유]]`: 작업 진행 상태 표시 및 연속 턴/대기 제어.
- `[[CALL:이름]]`: 후속 에이전트 호출.
- `[[TO:이름]]`: 해당 에이전트에게만 1:1 전달.
- `[[AFTER:이름]]`: 지정한 에이전트가 턴을 끝낼 때 깨움(`registerPeerWaiter` / `wakePeerWaiters`).
- `[[SPAWN:cli/model:name:task]]`: 현재 에이전트 아래 서브에이전트 생성(부모당 최대 3개).
- `[[DELEGATE:name|task|files|doneCriteria]]`: **자기 밑의 상주 서브에이전트**에게 작업 카드 생성 및 지시 전달. 다른 에이전트에게 일을 맡기려면 작업 카드에서 담당자를 지정한다(담당자를 깨우는 처리는 `handoff.change`의 `onCreate`).
- `[[HANDOFF_COMPLETE:카드번호]]`: 관리형 에이전트가 결과 보고와 함께 카드 상태를 갱신한다. 별도 검증자가 있는 카드에서 담당자가 쓰면 검증 대기로 전환되고, 검증자가 쓰면 완료된다. MCP 도구를 사용할 수 없는 세션에서도 이 태그로 보고할 수 있다. 허브는 현재 방의 카드와 최신 개정을 조회하고 MCP와 동일한 상태·권한 검사를 적용한다.
- 검증 요청을 받은 에이전트는 결과를 검토한 뒤 완료를 보고한다. 소유권 제안을 수락하거나 거절하는 절차는 소유권 인계 알림에만 적용된다.
- `[[NOT_CALL_PARENT]]`: **서브에이전트 전용.** 이 답은 부모를 깨우지 않아도 될 때(진행 메모, 방에만 보여 줄 말) 그 줄에 단독으로 쓴다. 태그가 없으면 부모가 깨어난다. 코드 블록 안이나 문장 중간에 있으면 무시한다. 예전에 안내했던 `[[CALL_PARENT]]`는 아무 효과 없이 화면에서만 지워진다. 서브에이전트에게는 이 규칙이 매 턴 정책 문구(`subagentPolicy`)로 전달된다.
- `[[AGENT_ROOM_NO_REPLY]]`: 응답이 불필요할 때 출력(방에 저장하지 않음).

## 3.3 정책 자동 동기화 (`policyHash`)
- `hub.cjs`의 `cliTurn`은 `replyPolicy` 문자열로 `policyHash`를 계산해 `cli_sessions.policy_version`과 비교합니다.
- 정책 문구가 바뀌면 기존 세션에도 `(Room policy updated; it replaces the earlier one.)`와 함께 전체 `replyPolicy`를 자동 재전송합니다.

## 3.4 사용량 한도(`usage_limit`) 처리 및 경고
- `cliTurn`에서 `error.cliCode === 'usage_limit'` 발생 시 `recordQuotaLimit()`으로 쿨다운 시각을 기록하고 `last_cli_error`를 갱신합니다.
- 기존 경고가 없을 때(`!limitNotified.has(participant)` 및 직전 `last_cli_error`가 `usage_limit`이 아닐 때)만 채팅방에 경고 메시지를 1회 남기고, 정상 턴 완료 시 `limitNotified`를 초기화합니다.

## 3.4b 조율 종료 · 중단 · [AGREED]
- `/조율중단`(`/회의중단`, 멈춰·그만)은 방의 의견·조율 단계를 모두 `stopped`로 끝내고, 진행 중이던 발언이 늦게 와도 `coordinateTurn`이 버린다(다음 라운드·실행 없음).
- 종료는 `endCoordination(plan, kind)`가 `⏹ 조율 종료 · 합의 완료 / 사용자 중단 / N라운드 소진`으로 표시한다. 중단·소진이면 마지막 발언자에게 `[조율 정리 요청]`을 보내 합의된 점·남은 이견·실행 여부를 한 번 정리시킨다(작업 시작 금지). 회의 합의는 허브의 종료 표시 다음에 정리 요청을 한 번 보내고, 작업 합의는 작업 보고로 대신한다.
- 변경 없는 동의는 note를 정확히 `[AGREED]`로만 쓰게 하고, 이때 앞 라운드에서 정한 files·work를 유지한다.

## 3.5 아키텍처 문서 자동 관리 (`archDocs`)
- 앱 설정(`local/app-settings.json`의 `archDocs`, 기본 켜짐, 앱 설정 > 실행 · 연결에서 토글, `set_app_setting` 액션)으로 켜고 끈다.
- 켜져 있으면 DEV 모드 턴마다 `ensureArchitectureDocs(project)`가 작업 폴더에 `ARCHITECTURE.md`가 없을 때 목차 틀을 만든다(첫 줄 `<!-- agent-room:architecture-skeleton -->`). 정책 문구에 "목차와 영역 문서를 읽고, 바꾸면 같은 변경에서 영역 문서를 갱신하고, 틀 표시가 남아 있으면 코드를 읽고 채운 뒤 표시를 지우라"는 지시가 들어간다.
- 꺼져 있거나 CHAT 모드면 파일을 만들지 않고 정책에서도 문서 지시를 뺀다.
- **방별 설정 (`rooms.arch_docs`, `roomArchDocs`, `set_room_arch_docs`):** 방의 폴더 창에서 "앱 설정 따름 / 켜기 / 끄기"를 고른다. 값이 NULL이면 앱 전역 설정을 따른다. 방마다 대상 프로젝트가 달라서(예: 문서가 필요 없는 실험 폴더) 전역 스위치 하나로는 부족했다.

## 설계 의도 (왜 이렇게 했나)

- **Claude 카드의 "세션 연결 중" 깜빡임 (오퍼스):** Claude CLI는 재사용 중인 프로세스에서도 턴마다 `system/init`을 다시 보낸다. 그 뒤 첫 도구나 글이 나올 때까지 모델이 생각하는 시간(`local/claude-turn-timing.jsonl` 55턴 기준 중앙값 3초, 상위 10% 9초)이 "세션 연결 중"으로 보여서, 매 턴 다시 연결하는 것처럼 보였다. 실제 연결은 40ms 안에 끝나므로 init은 "생각 중…"으로 표시한다.

- **[[CONTINUE]] 답장 안의 [[CALL]]도 전달 (오퍼스):** [[CONTINUE]]로 끝난 답장은 허브가 같은 에이전트를 다시 실행하는 `shouldNudge` 경로를 탄다. 이 경로가 답장 라우팅(`routeAgentReply`) 전체를 건너뛰어서, 일을 나눠 주며 쓴 `[[CALL:솔]]`, `[[CALL:테라]]`가 전달되지 않았다. 이제 `called`가 있으면 라우팅을 한다.

- **조율 중단과 종료 표시 (오퍼스, 솔 요청):** 사용자가 멈출 방법이 없었고, 끝난 이유(합의/중단/소진)가 채팅에 드러나지 않았다. 동의만 할 때 긴 문장을 반복해 라운드가 길어지던 문제로 `[AGREED]` 단독 규칙을 넣었다.

- **Codex 턴마다 샌드박스를 명시 (오퍼스):** 이어 쓴 Codex 스레드는 마지막 턴의 샌드박스 모드를 기억한다. 읽기 전용 조율 턴 뒤에 솔·테라가 계속 읽기 전용으로 갇힌 사고(v1.0.38) 때문에, 앱 서버의 `thread/resume`과 `exec resume` 모두 권한에 맞는 `sandbox`(대화=read-only, 개발=workspace-write, 전체=danger-full-access)를 매번 지정한다.

- **아키텍처 문서를 앱 기능으로 (오퍼스):** 세션을 놓치거나 새로 합류한 에이전트가 구조와 의도를 바로 파악하게 하려고, 이 저장소에서만 쓰던 방식을 모든 개발 프로젝트로 넓혔다(사용자 요청). 원치 않는 프로젝트도 있을 수 있어 설정에서 끌 수 있게 했다.

- **조율은 메인 세션에서 (오퍼스):** 예전엔 조율 발언을 일회성 CLI로 돌려서, 조율하는 쪽은 무엇을 조율하는지 모르고 결과는 메인 세션이 몰랐다(seq 2708~2731: 테라·솔이 자기가 참여한 조율을 "없었다"고 답함). 그래서 메인 세션을 읽기 전용 턴으로 이어 쓰고, 조율 메시지는 모든 에이전트에게 참고로 전달한다. 일회성으로 되돌리지 말 것.
- **조율 최대 6라운드 (오퍼스):** 3라운드에서 합의 직전에 멈춘 사례 때문에 늘렸다.
- **`/조율`·`/회의` 명령 (오퍼스):** 판정 모델이 "실행까지 하라"는 뜻을 알아챌 때만 조율이 켜져서 사실상 안 쓰였다. 사용자가 확실히 켤 수 있게 명령으로 만들었다.
- **작업 카드는 담당자를 깨우고 중복은 막는다 (오퍼스):** 카드만 생기고 담당자가 깨어나지 않던 사고(#2~#4 중복 포함) 때문.
- **태그 이름은 id가 아니라 표시 이름 (오퍼스):** 사용자가 프롬프트에 id가 보일 필요가 없다고 했고, 이름 중복은 생성 시 막는다.
- **0% 한도 에이전트는 순위·판정에서 제외 (오퍼스):** 불러도 답할 수 없어서 대화가 멈추는 것을 막으려고.
- **`usage_limit` 시 방 경고 1회 출력 (수소):** 요즘 모델이 한도 도달 시 별도 안내 없이 빠르게 종료하고, 기존 허브는 카드 `cliError`만 바꿔 채팅창/원격에서는 멈춘 이유를 놓치기 쉬웠다. 기존 경고가 없을 때만(`!limitNotified` + 직전 `last_cli_error`가 `usage_limit` 아님) 방에 1회 경고를 남기고, 정상 턴 완료 시 초기화해 도배를 막는다.
- **서브에이전트의 답이 기본으로 부모를 깨우고, 깨우지 않을 때만 태그를 쓰게 한 이유:** 서브에이전트는 부모가 맡긴 일을 하는 존재라서 대부분의 답이 부모가 검토해야 하는 보고다. 기본을 "깨움"으로 두면 태그를 빼먹어서 부모가 결과를 모르고 일이 멈추는 일이 없다. 진행 메모처럼 부모가 볼 필요 없는 답만 사용자가 요청한 대로 `[[NOT_CALL_PARENT]]`로 의도적으로 표시한다. 처음에는 요청을 반대로 이해해 "태그가 있어야만 깨우는" 방식(`[[CALL_PARENT]]`)으로 만들었다가 바로잡았다. 같은 실수를 하지 않도록 남긴다: 태그는 **예외를 표시하는 쪽**에 둔다.

> 상위 목차: [ARCHITECTURE.md](../../ARCHITECTURE.md)

- 의견 및 회의 요약은 읽을 맥락으로만 전달한다. 세션 로그 미러는 허브에서 처리한 응답과 회의용 JSON을 다시 게시하지 않는다. 직전 회의가 합의로 끝난 상태에서 사용자가 시작을 승인하면 허브가 담당자에게 직접 전달한다.
