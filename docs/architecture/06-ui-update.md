# UI · 모바일 · 업데이트

- **작성 중인 초안:** 탭의 세션 저장소에 방별 텍스트를 저장해 다른 방을 열었다 돌아와도 복원한다. 전송에 성공하면 보낸 방의 초안이 전송 당시와 같은 경우에만 비운다.
- **진행 흐름:** 요청 아래에는 진행 흐름 요약을 표시한다. 순위, 응답, 위임 및 후속 호출 기록은 요약을 펼쳐 확인한다.

- **첫 화면 환경 점검:** 대화가 비어 있을 때 기존 자가 진단의 결과와 항목별 다음 행동을 보여 준다. 진단이 실패하면 오류와 다시 점검 버튼을 남긴다. 명령줄 도구 감지는 설치 여부만 나타내며, 로그인과 실제 응답은 첫 요청으로 확인한다.

- **키보드 스크롤 보정 (`syncPhoneHeight`):** `index.html`과 `remote-site/page.html` 모두 `visualViewport.height`가 줄어들고 입력창(`#draft`)에 포커스가 있을 때만 메시지 목록(`#messages` / `#history`)의 `scrollTop`을 `delta`만큼 올립니다.
- **스크롤 두 가지:** 키보드가 올라올 때는 보고 있던 위치를 화면 높이 변화만큼 보정하고, 새 원격 메시지가 오면 열려 있는 대화의 맨 아래로 이동한다. PC에서 검색 중이거나 폰에서 이전 기록을 더 불러오는 중에는 읽던 위치를 유지한다. 두 동작은 따로 검증한다.
- **스크롤의 설계 의도:** 키보드를 열 때 입력창에 가리는 만큼만 대화를 올려, 사용자가 읽던 메시지를 계속 볼 수 있게 합니다. 열린 방에 새 원격 메시지가 도착하면 확인할 수 있도록 맨 아래로 이동합니다. 검색이나 이전 기록 불러오기는 사용자가 보는 위치를 보존해야 하므로 이 이동에서 제외합니다.
- **인라인 `<script>`가 2개:** `index.html`에는 메인 스크립트 위에 독립된 크래시 복구·`uiStamp` 자동 새로고침 스크립트가 하나 더 있다. 검사할 때는 `matchAll`로 **모두** 검사한다.
- **모바일 채팅 한도 텍스트:** 모바일에서는 에이전트 카드 대신 채팅 메시지 보낸이 이름 옆에 해당 모델의 남은 한도 텍스트를 표시합니다.
- **업데이트 (`updater.cjs`, `update.ps1`):** `local/update.log`의 인코딩(UTF-8 / EUC-KR 폴백)과 마지막 상태 줄을 `readUpdateStatus()`가 판정해 진행 중·PC 재연결 대기·새 버전 실행 확인 완료·실패를 상단 배너와 설정 창에 표시합니다.
- **업데이트 흐름:** `shutdown_for_update`는 에이전트가 일하는 중이어도 바로 허브를 재시작한다(이미 재시작 중일 때만 409). 진행 중이던 턴은 재시작 뒤 `recoverWarmTurns`·`recoverDetachedTurns`가 다시 대기열에 넣고, 대기 중이던 순위 판정은 다시 돌며, 새 메시지는 outbox에서 기다린다. `update.ps1`은 SHA-256 검증 → 임시 폴더(`agent-room-update-*`)에 백업 → 파일 교체 → 새 허브 응답 확인 순으로 가고, 실패하면 백업으로 롤백한다.
- **업데이트 도중 전원 꺼짐 복구:** 파일을 바꾸기 직전 `update.ps1`이 `local/update-in-progress.json`(백업 위치·파일 목록·업데이터 PID)을 만들고, 성공 또는 롤백이 끝나면 지운다. 허브가 시작할 때 이 파일이 남아 있고 업데이터가 죽어 있으면 `recoverInterruptedUpdate()`가 백업에서 파일을 복원하고 허브를 다시 띄운다(`AGENT_ROOM_NO_UPDATE_RECOVERY`가 있으면 건너뜀). 백업이 이미 지워졌으면 표시 파일만 지운다.

- **업데이트 영향 표시:** 화면에서 [업데이트 설치]를 누를 때 작업 중인 에이전트가 있으면 이름과 "지금 설치하면 끊기고 재시작 뒤 다시 실행"을 확인 창으로 보여 준다(기본은 여전히 즉시 설치). 재시작 때 `recoverWarmTurns`가 다시 대기열에 넣은 턴은 `restartRecovery`로 `/state`에 실리고, 업데이트 완료 배너가 1시간 동안 "끊긴 작업 N개: 이름(복구 완료/다시 실행 중/복구 실패)"을 실시간 전달 상태로 보여 준다.

## 설계 의도 (왜 이렇게 했나)

- **영향 표시만 넣고 기본은 즉시 설치 (오퍼스):** 사용자가 기다리지 않는 업데이트를 원했고(재시작 후 복구), 회의 합의대로 무엇이 끊기는지와 복구 결과만 보이게 했다.

- **업데이트는 에이전트를 기다리지 않는다 (오퍼스):** 사용자가 "먼저 받는 애가 있으니 안전하다"며 요청했다. 끊긴 턴은 복구 기능이 다시 대기열에 넣는다.
- **답변 추천 버튼 제거 (오퍼스):** 사용자 요청.
- **원격 에이전트 카드 `.act-head-actions` 묶음 (수소):** `.act-head`가 `justify-content: space-between`일 때 `이름`·`설정`·`일시정지`를 직접 자식으로 두면 `설정`이 가운데로 밀려 버튼 사이 여백이 생긴다. 두 버튼을 `.act-head-actions`로 묶어 오른쪽에 나란히 붙였다.
- **모바일 한도 표시 위치 `.chat-quota` (수소·네온):** 처음엔 에이전트 창 이름 옆(`.act-quota`)에 붙였으나, 모바일에서는 패널을 열지 않고 대화 흐름에서 바로 잔여 한도를 보는 편이 나아 채팅 작성자 옆(`.chat-quota`)으로 옮기고 에이전트 창 표시는 제거했다.

- **업데이트 도중 전원 꺼짐 복구를 둔 이유:** 파일 교체는 여러 파일을 차례로 복사하므로 중간에 끊기면 새 파일과 옛 파일이 섞여 허브가 못 켜질 수 있다. 업데이터 자신은 전원이 꺼지면 돌 수 없으므로, 복구는 업데이터가 아니라 **허브가 시작할 때** 한다.
- **복구 안전 조건의 이유:** 업데이터가 아직 살아 있으면(정상 업데이트 중) 허브 시작이 복구를 건드리지 않는다. 표시 파일이 가리키는 백업 위치가 임시 폴더 밖이거나 복원 경로가 설치 폴더를 벗어나면 거부한다. 표시 파일을 바꿔 임의 경로에 파일을 복사하게 만드는 것을 막기 위해서다.
- **허브 예외를 기록하고 계속 실행하는 이유:** 원격 중계를 못 띄우는 사소한 오류 하나로 허브가 죽으면 진행 중인 모든 에이전트 턴이 끊긴다. 그래서 `uncaughtException`과 `unhandledRejection`은 `local/hub-errors.log`에 남기고 계속 간다. 다만 포트 충돌·DB 손상은 계속 돌면 데이터가 더 망가질 수 있어서 종료한다.
- **`hub.json`을 임시 파일로 쓴 뒤 교체하는 이유:** 원격 중계와 업데이터가 이 파일을 허브 재시작 중에도 읽는다. 반쯤 쓰인 JSON을 읽어 토큰·주소를 잘못 얻는 일을 막는다.
- **화면 코드의 선언 순서 교훈:** `renderHistory` 같은 큰 함수에서 `const`를 선언 전에 쓰면 "Cannot access … before initialization"으로 화면이 로딩되지 않는다(`isOwn` 사례: 모바일 한도 표시 코드가 선언보다 위에서 사용). 새 코드를 끼워 넣을 때는 쓰는 변수가 이미 선언됐는지 확인한다.
