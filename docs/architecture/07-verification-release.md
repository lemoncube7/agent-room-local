# 변경 후 검증 체크리스트

수정한 영역에 따라 아래 명령으로 검증합니다:
- JS 문법 검사: `node --check hub.cjs` (수정한 `.cjs` / `.mjs` 대상)
- 인라인 스크립트 검사: `index.html`(스크립트 2개), `remote-site/page.html`의 **모든** `<script>`를 `matchAll`로 추출해 각각 `new Function(code)`
- 허브 통합 테스트: `node smoke-test.cjs` (1~2분 걸린다. 짧은 제한 시간으로 돌리면 실패처럼 보일 수 있다)
- 흐름 회귀 테스트: `node flow-regression-test.cjs` (약 10초, `release.ps1`이 `smoke-test.cjs` 다음에 자동 실행). 현재 포함: ⓪ 포트 충돌(다른 프로그램이 4317을 쓰면 다른 포트로 이동, Agent Room 허브가 있으면 두 번째 허브 종료, 명시한 ROOM_PORT는 이동하지 않음)과 중계의 hub.json 주소 검사(루프백 아무 포트는 허용, 다른 호스트는 요청 전에 거부), ① 설정 도우미 허용 목록이 `hub.cjs`의 `ASSISTANT_ACTIONS`(+`report_issue`)와 `index.html`의 `splitAssistantActions`에서 같은지, ② 업데이트가 끊겼을 때 표시 파일과 백업으로 복원되는지(경로 이탈 파일은 건너뜀), ③ 백업이 임시 업데이트 폴더 밖이면 복원하지 않고 표시 파일만 지우는지, ④ 업데이터가 아직 살아 있으면 복원하지 않는지. 이 파일에 새 테스트를 추가할 때는 임시 폴더에 허브를 복사해 띄우는 방식(`makeRoot`/`startHub`)을 따른다. 같은 요청 ID 재시도 시 한 번만 저장되는 검사는 `smoke-test.cjs`의 `remote_user_message` 부분에 있다.
- 원격 릴레이/다중 노드 테스트: `node remote-site/smoke-test.mjs`
- Cloudflare 자동 설정 테스트: `node cloudflare-setup-test.cjs`

## 깨끗한 Windows 설치 · 첫 답변 · 로그인 복구 검증

이 시나리오는 **실제 Windows 기기 또는 격리된 새 VM**에서 릴리스 ZIP으로 수행한다. 기존 개발 PC나 모의 CLI에서 통과한 결과만으로 깨끗한 환경 검증에 성공했다고 표시하지 않는다. 시작 전에 Windows 에디션·빌드·언어·아키텍처, 앱 버전과 ZIP 해시, Node.js·WebView2·선택한 CLI의 설치 여부와 버전, 네트워크 환경을 기록한다. 미설치 상태와 설치된 상태를 구분하고, CLI마다 별도로 결과를 기록한다. 계정·토큰·쿠키·대화 내용은 기록에 넣지 않는다.

1. **설치와 실행:** 새 사용자 환경에서 배포 ZIP의 체크섬을 확인하고 쓰기 가능한 폴더에 압축을 푼다. 안내에 따라 `Agent Room.exe`를 실행한다. 사전 구성 요소가 없다면 표시된 안내와 필요한 사용자 조작을 기록하고, 설치 후 다시 시작한다. **통과:** 앱 화면이 열리고 빠진 항목과 다음 행동을 이해할 수 있으며, 기존 설정이나 파일을 임의로 덮어쓰지 않는다. 설치 경고나 외부 설치가 필요했다면 숨기지 않고 기록한다.
2. **첫 답변:** 사용할 CLI 하나를 설치·로그인하고 안내에 따라 방과 에이전트를 준비한다. `파일은 수정하지 말고 한 줄로 인사해 주세요.`를 보낸다. **통과:** 요청이 화면에 나타나고 선택한 에이전트의 실제 답변이 도착한다. 실행 파일 감지나 로그인 창이 열린 것만으로 통과시키지 않는다. 작업 폴더 선택이 요구됐다면 실제 요구 여부도 기록한다.
3. **로그인 복구:** 격리된 테스트 계정 또는 테스트용 CLI 환경에서만 로그아웃해 인증이 필요한 상태를 만든다. 다시 요청한 뒤 화면의 안내로 로그인하고 같은 방에서 새 요청을 보낸다. **통과:** 인증이 필요한 사실과 다음 행동을 확인할 수 있고, 로그인 후 실제 답변을 다시 받으며 기존 방과 대화가 유지된다. 테스트 때문에 기존 사용자의 계정 세션을 임의로 로그아웃하지 않는다.

각 단계의 결과는 `통과 / 실패 / 미검증`과 시각, 관찰한 화면·실패 단계·재현 조건을 함께 남긴다. 깨끗한 기기나 VM, 해당 CLI·테스트 계정, 인터넷 접근 또는 실제 응답을 확보하지 못하면 관련 단계를 **미검증**으로 기록한다. 로그인 만료를 재현하지 못하고 수동 로그아웃만 시험했다면 그 차이도 기록한다. 자동 테스트 통과는 실제 설치·로그인·응답 검증을 대체하지 않으며, 원격 연결·휴대폰·다른 Windows/CLI 조합은 이 시나리오를 통과했다는 이유만으로 검증된 것으로 취급하지 않는다.

## 릴리스 · 배포 주의
- 릴리스 명령은 `E:\agentroomfolder\release.ps1 -Version X -Commit HEAD`. VERSION·CHANGELOG 갱신과 커밋을 먼저 해 둔다.
- **새 파일을 추가하면 `release.ps1`의 `$files` 목록에도 넣는다.** 빠지면 릴리스 ZIP에서 누락된다. (`update.ps1`은 ZIP 안의 파일을 모두 설치하므로 목록은 `release.ps1` 쪽이 기준이다.)
- 원격 페이지·Worker를 바꿨다면 새 버전 설치 뒤 Cloudflare 자동 설정을 다시 실행해 Worker를 재배포해야 폰에 반영된다. 수동 `wrangler deploy`를 쓴다면 `wrangler.toml` 기본 이름(`agent-room-remote`)이 아니라 `local/remote-config.json`의 `site` 호스트명(`agent-room-<12hex>`)으로 `--name`을 지정한다.
